## 二、课题背景与意义

安全帽佩戴检查可以借助图像检测，为人工巡查提供可回查的辅助提示。在RK3568边缘设备本地完成推理，有助于减少持续云端连接与主机计算依赖，但必须处理模型兼容、输入输出契约、缓冲、结果时效、故障和输出开销。检测到目标、没有检测到目标和检测不可用需要分别表达，不能用旧画面或空检测推断现场安全。

本课题围绕单路输入和现成YOLOv5社区模型，构建原帧绑定的检测与提示系统。通过固定来源数据、真板结果、计时和故障记录研究配置取舍。项目价值在于可追溯的工程实现和实验判断，不预先宣称新的轻量网络或检测算法。

使用方向为开发板屏幕直接操作：打开本地 App 选择模型/输入、开始/停止和查看原帧提示。检测使用本地模型与真实 USB 相机可离线运行；WiFi 在用户需要联网时手动连接，SCP 用于完整包复制更新。systemui 重载后的手指图标、独立供电、WiFi 关联/DHCP/保存与长期现场保留为本次交付限制。

## 三、相关技术与采用路线

### 3.1 国内外相关工作与可查参考

通用目标检测框架已提供推理、模型导出与后处理基础。[Ultralytics YOLOv5官方仓库](https://github.com/ultralytics/yolov5)是本项目anchor-based接口的通用背景；采用既有社区权重不构成自主算法训练，也不能未经输出核验直接换为YOLOv8/DFL结构。

面向Rockchip芯片的[官方rknn-toolkit2](https://github.com/airockchip/rknn-toolkit2)和[rknn_model_zoo](https://github.com/airockchip/rknn_model_zoo)提供转换/部署参考，适合优先核对预处理、tensor布局和runtime版本。它们支持端侧工程路线，但上游示例可运行不自动证明本应用的精度、原帧时效、稳定性或实际显示。

已有[helmet_yolov5_rknn_deploy社区项目](https://github.com/harperjuanl/helmet_yolov5_rknn_deploy)提供本仓库沿用的安全帽模型/板端路径，说明无需训练即可开展部署实验；缺原训练manifest/完整校准谱系时，来源独立性仍须披露。标签数据方面，[SHWD](https://github.com/njvisionpower/Safety-Helmet-Wearing-Dataset)与[SCUT-HEAD](https://github.com/HCIILAB/SCUT-HEAD-Dataset-Release)及精确HardHat发布有裸头/帽与全身person语义、difficult和素材权利差别，不能只做类名替换后宣称标准独立benchmark。

因此本课题定位为**工程实现与端侧受控评价**：在既有检测算法上建立可追溯模型和输入契约、质量与成本对照、原帧时效及故障记录。以上仓库提供工程参考；正式文献综述还需检索相关论文，比较其研究问题、方法、数据和实验条件。现有实现与测量支持工程贡献，算法创新需要另有方法和实验依据。

### 3.2 采用的技术路线

YOLOv5 anchor-based模型以框、objectness和类别输出完成头部检测；模型`person`表示裸头、`hat`表示戴帽头部。全身人物与头部框是不同标签单位，必须在来源映射时区分。输入尺寸可能改变小目标信息，量化与工具链也可能影响分数和框；这些因素需要通过受控比较说明。

部署采用Python、RKNNLite、OpenCV和NumPy。共享解码支持原始legacy检测头和裁剪Conv头，转换侧以Toolkit2 2.3.2为当前基线。YOLOv8/DFL等输出不能只换模型文件后沿用现有解码。CPU浮点ONNX与板端INT8的时间差不能证明量化加速；量化单因素结论需要同源、同尺寸、同工具/裁剪/校准规则的FP16与freshINT8真板配对。

异步流水线以独立frame ID和应用读取时间绑定输入与结果，控制最新帧邮箱、源中断代次、TTL、报警持续判定/冷却，以及慢sink期间的有效性。记录采集、独立检测、输出和显示各自的计数与延迟，避免只展示一个FPS。

板屏采用预装Qt Quick/QML，Python LocalService只监听127.0.0.1并校验私有会话令牌，DetectionController复用Pipeline/RKNNLite。预览绑定run generation、source epoch、frame ID与原采集时间/TTL，停止、错误或过期隐藏旧图。WiFi后端提供状态/扫描及用户点击连接、内置密码键盘与可选保存；实际自动验证只读，不切换当前网络。屏上没有日志导出/音量/MPP/Web开关，CLI输出与实验能力按各自路径评价。

## 四、研究与工程内容

1. **现成模型来源与契约核验。** 保存社区模型/ONNX来源、文件SHA、类别、预处理、输出布局和runtime。保留原模型与五种既有输入配置，未经新证据不归因于某个单一优化。
2. **规范化诊断数据与真板评估。** 获取并固定来源子集，保留raw/XML/许可/选择/hash，使用明确坐标和类别规则生成COCO。逐图导出既有RKNN预测，区分正常空检测与推理失败，计算两类AP50/P/R/F1、小目标分桶与误检漏检图。
3. **可信检测与提示。** 统一图片、视频、摄像头/网络源接口，结果绑定原帧；实现过期/故障传播、持续报警和有界音频、事件/定时截图、逐帧与会话统计。空检测和源中断不显示全员安全。
4. **板屏应用与可回查输出。** Qt本地App提供全屏连续预览、开始/停止、回桌面常驻、单实例复用、WiFi状态/扫描/键盘与手动接入。Web/事件切片作为CLI另一输出保留对应帧、覆盖/缺口与失败；systemui重载后的手指操作、真实网络切换和长期声音/事件质量另验。
5. **运行、故障和配置评价。** 分别评价旧Pipeline API长跑、App回放30分钟、v4-r2正式入口180秒、本机服务/Qt/HTTP/截图日志、资源/直接清理、故障与恢复，以及同源量化与编码对照。不同入口和时长不能互相替代；现场和独立质量门槛具备后才正式选型。

## 五、当前数据与评价口径

本轮使用两个在推理前固定的200图诊断子集。SHWD是原test.txt前200IDs，共998GT：212裸头、786戴帽；139个difficult帽目标按include-as-normal保留并正常计算漏检，因此不是官方VOC difficult-ignore/SHWD基准。HardHat为Kaggle精确v1来源列表前200标注名，共956GT：262head和694helmet，35全身person明确忽略。七个SHWD文件名声明差异有原名、实际名、解析和hash记录，不改raw或删图。

SHWD仓库MIT不能推断所有图像的再分发权，SCUT-HEAD成分注明学术研究用途；HardHat该发布metadata为CC0。两来源训练重叠未知，已确认一张共同照片；没有可信scene/session ID，保留一个未知场景组，不能伪造独立train/val/test。详细依据见 [来源与许可](../experiments/2026-11-14/data-acquisition/SOURCE_AND_LICENSE.md)。

项目AP50为IoU`.5`下的all-point插值，保留score floor`.001`，工作置信度`.25`、NMS`.45`；不等于官方COCO AP50:95或full-score-range AP。高floor结果明确标truncated，不参与项目门槛判定；无GT类别为null。业务报警召回/误报警/延迟需要标注事件视频，不能由框mAP替代。

## 九、主要风险与应对

训练来源/场景独立性不足时只作诊断结论；小目标与裸头召回不足时报告现有配置差异，不调测试阈值制造通过；物理源缺失时推进可复用软件和回放验收，同时保留物理门槛；FP16/编码环境失败时保留实际日志，不能用不同后端计时或无效文件填补对照。未全部通过质量、现场和稳定性门槛前不指定最终模型。

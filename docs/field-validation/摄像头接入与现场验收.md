# 摄像头接入与现场验收

版本 2026年11月15日

本手册用于设备到位后复用现有输入、检测、报警与输出链路。当前已记录USB相机90帧实际采集及一次12秒CLI核心检测，详见[接入进展](../experiments/2026-11-15/摄像头到位与接入准备记录.md)；App相机/后台、拔插、相机长跑、人工板屏和声音、手机观察或独立现场精度仍未验收。本文件仍是后续现场执行准备，空模板不是已通过的现场记录，不把已有短run填作所有门槛成功。

当前系统沿用社区YOLOv5模型，不训练、不微调、不剪枝、不蒸馏。模型类别`person`为裸头，`hat`为戴帽头部。现场演示是人工巡查辅助，空检测或检测不可用都不能表示全员安全。

## 1 资料与参数核对

先读[项目手册](../项目蓝图与完整手册.md)、[当前范围](../superpowers/plans/2026-11-14-graduation-scope.md)、[App手册](../app/板端App使用手册.md)与[当前安装记录](../experiments/2026-11-15/原生App安装与独立运行验证.md)。用[field-run-template-v2.json](field-run-template-v2.json)复制一份新的现场记录，填写测试负责人、日期、实际入口、板卡与摄像头型号、安装位置、模型/输入/源码SHA、配置及预设接受条件。较早[field-run-template.json](field-run-template.json)保留原样，不覆盖模板或既有实验。

先决定本轮走原生Qt App还是CLI。App已安装在历史目录名`/userdata/helmet-validation/20261115-native-app-v2`，发布身份是WiFi-only v3；以[发布清单](../experiments/2026-11-15/native-app/bundle-manifest-v3.json)和[板端收据](../experiments/2026-11-15/native-app/v3-installed-release.json)核对实际文件，不能用目录中的v2判定源码版本。记录wrapper目标、launch/service/QML/WiFi及模型身份。新现场结果使用独立编号，正常退出后只复制非敏感日志/产物。

以下CLI参数依据`helmet/helmet_realtime.py --help`及`build_parser()`核对。CLI示例用现有416性能候选、conf.25/NMS.45，不代表正式选型。App固定conf.35/NMS.45/skip0/TTL1秒，屏上不能编辑这些阈值；启动前记录所选模型、源与回放profile，停止完成后才能更换。回放10/20FPS是请求节奏，设备采集另测，默认列表可能首先显示原640模型。工作点在测量前固定，不能根据测试结果调参后改写第一次记录。

| 参数 | 含义与现场限制 |
| --- | --- |
| `--source` | 图片、录像、摄像头节点、数字索引或RTSP；更换源通过停止当前会话再启动新会话完成 |
| `--model` | 显式RKNN路径；当前没有运行期模型热替换 |
| `--cam-w`、`--cam-h` | 请求采集尺寸，实际协商尺寸另测，不保证设备接受 |
| `--replay-fps` | 图片/文件录像节奏；不是摄像头FPS配置，摄像头不使用文件pacer |
| `--conf`、`--nms`、`--skip` | 置信度、NMS和每N+1个消费帧检测一次；验收固定skip0 |
| `--result-ttl` | 从应用读取原帧到输出的有效期限；不能当成传感器曝光延迟 |
| `--duration` | 时限退出，0持续；`--shutdown-timeout`是worker正常停机等待，不保证中断native挂死 |
| `--no-display` | 无本地窗口，仍可保存日志与启用Web；板屏测试时去掉 |
| `--save-dir`、`--save-interval` | 新鲜报警/手动/定时截图；定时秒数不代表独立检测FPS |
| `--alarm-dwell`、`--alarm-cooldown`、`--alarm-clear` | 持续证据、冷却和解除窗口；新鲜独立结果参与状态机 |
| `--alarm-beep`、`--audio-timeout` | 启用音频；当前默认调用`aplay -q /oem/alarm.wav`，没有CLI音频路径参数 |
| `--jsonl`、`--session-json` | 任一启用完整记录及资源sidecar，最后精确磁盘分位；每轮新路径 |
| `--web-host`、`--web-port` | 默认127.0.0.1/0，0关闭；LAN查看显式0.0.0.0 |
| `--clip-dir`、`--clip-pre`、`--clip-post` | 事件切片目录及前后秒数；必须检查连续覆盖和不可用mask |
| `--clip-fps`、`--clip-encoder` | 编码节奏与`opencv`或`mpp`，不是独立检测吞吐 |

## 3 确认实际采集设备和格式

本次[新枚举](../experiments/2026-11-15/camera-connected-1.json)已发现USB `1bcf:0b09`/`UNIQUESKY_CAR_CAMERA`，`uvcvideo`的 `/dev/video10` 为 Video Capture、`/dev/video11` 为 Metadata Capture；MJPG支持640×480@30 FPS，YUYV支持640×480@20 FPS。此前只有root hubs/内部ISP的[预检](../experiments/2026-11-15/camera-preflight-1.json)和未绑定sensor的[拓扑](../experiments/2026-11-15/camera-topology-1.json)仍是原时点观察，不代表这次USB相机不可用。后续重新插接仍需复查节点编号及Device Caps，不选metadata11或ISP0–9替代本次实际capture源。

摄像头接好后，先在板端执行只读枚举并保存输出：

```text
v4l2-ctl --list-devices
v4l2-ctl -d /dev/videoX --all
v4l2-ctl -d /dev/videoX --list-formats-ext
```

`/dev/videoX`替换为确切采集节点。ISP、编码器、解码器或`/dev/video-camera0`链接存在不证明真摄像头有图。记录节点真实路径、设备名、driver、总线、支持像素格式、分辨率和帧间隔；读取链接只作身份核对，不能假定固定video编号。

当前`VideoSource`对`/dev/video...`路径使用V4L2，并请求MJPG、640×480或所填`--cam-w/h`。CLI没有`--pixel-format`或`--camera-fps`。设备必须能支持该请求，或者明确记录实际协商/后端行为。不能在文档加入不存在参数解决格式问题；若设备只支持其他格式，应先建立有证据的兼容问题，再修改和验证输入实现。

采集检查先短后长，保存真实图像/视频或独立抓帧结果、解码尺寸、格式、驱动/应用计时与退出码。可在选定节点上使用设备支持的`v4l2-ctl --stream-mmap`工具作诊断，采集产物路径必须指向此次隔离根；根据实际帧率设置数量和外部超时，保存超时或失败，不能把任意字节文件当作已解码视频。不要同时让独立抓帧工具和应用占用同一节点。

表中“请求”与“实测”必须分开：请求分辨率/FPS、实际协商分辨率/FPS、成功解码帧尺寸、整段应用captured FPS、独立detected FPS、output/displayed FPS及计时边界。应用读取完成时刻不等于曝光时刻；若需要曝光到显示延迟，要另有外部同步测量。

## 4 用同一链路从回放切换为摄像头

已完成的有限核心短验见[准备记录](../experiments/2026-11-15/摄像头到位与接入准备记录.md)及[核验JSON](../experiments/2026-11-15/camera-npu-short-1-verification.json)：先用现有VideoSource取得90帧独特640×480/MJPG真帧并release，再以416/.35/.45/skip0/TTL1/no-display运行12秒CLI，actual elapsed12.071305765988654秒、279 captured/174 detected/173 output、read/detection failure均0，检测14.4143/输出14.3315 FPS。347条原始检测/输出记录、5次定时保存及当前原帧绑定保留。7/173输出含模型预测目标，标签正确性未验证，不是全空预测或精度成绩；CLI退出0/session停止也不自动证明App或直接SDK终态。

该run采用与App相同的.35置信度，但入口仍是既有CLI核心；下面.25示例属于另一固定工作点，复测应记录差异而不是改写旧run。后续v4-r2已补App真实相机连续预览、物理拔线TTL、正式入口隐藏/唤回、同generation复用、UI完整退出和196.67秒短跑，见[Phase 2终验](../experiments/2026-11-15/native-app-usability-v4-phase2-1/report.md)。本次no-display短验仍只归自身，不替代v4-r2；1800秒长期运行、独立供电和现场事件质量继续另验。

先做10秒回放检查，确认模型、代码和输出路径正常：

```powershell
ssh rk "cd /userdata/helmet-validation/NEW_FIELD_RUN/src && python3 helmet_realtime.py --model ../models/helmet_416x416.rknn --source ../input --conf 0.25 --nms 0.45 --skip 0 --replay-fps 10 --result-ttl 1 --no-display --duration 10 --jsonl ../results/replay.frames.jsonl --session-json ../results/replay.session.json"
```

等该进程终态并记录退出码后，再启动真实摄像头，使用新的日志：


短测确认后扩展到180秒真实采集，继而按冻结方案进行1800秒运行。不要复用短测日志路径。没有运行期source热替换开关；source参数改变就是新会话，两个会话分别保留身份。源中断后的同会话重连由源实现处理，恢复仍需真实成功read及新epoch结果。

核对每个输出的frame ID、captured_at、source_epoch、模型SHA、阈值及框；不得将旧框贴到新帧。同时记录覆盖、跳帧、读失败、推理失败和pending库存，不能只取窗口FPS截图说明吞吐。11月14日API回放长跑9.7724检测FPS仍是原run结果；[11月15日v2 App组合](../experiments/2026-11-15/原生App30分钟验证报告.md)约11.0030检测FPS来自私有验证包装器的单照片录像/416/完整日志配置，二者都不替代本次摄像头10FPS。当前正常launcher仅有短验证，长期正常启动验证是[新方案](../superpowers/plans/2026-11-15-normal-launcher-validation.md)的待执行项。

## 5 受控拔插与恢复

设备和进程均具备后，单独开一个新故障会话。先观察正常原帧和状态；记录拔出宣告的外部时刻，再物理拔出，保存producer首次实际failed read/源epoch失效及输出状态的时间。两者间可能有驱动缓存与调度延迟，不能声称宣告起0ms禁止所有旧帧。

producer观察失败后，旧epoch结果不得作为新健康预览、报警、音频或保存。Web应显示不可用，旧图应隐藏；断流期间不能把“未检测到裸头”解释为安全。重新插入并核对原设备是否仍在同节点；恢复要求真实成功读取、新epoch和新鲜检测，报警持续窗口重新累计。若重新枚举到另一节点，只能正常停止原会话，再以新source启动，记录为“新会话接入”，不能称原节点自动恢复。

另记录`--duration`或q/ESC正常退出、可捕捉信号停止、错误模型/坏源的非零退出。不能外杀Python线程作为常规故障注入，也不承诺断电、SIGKILL或不可中断native调用一定清理。长跑exit0不是直接SDK释放证明；若本次runner确实记录created/released/release_error、worker状态和超时，保留收据。没有收据则标为未记录，不能跨run复用故障suite释放记录。

## 6 板屏和音频人工验收

**原生App分支。** 主界面正常重新加载图标清单后，由现场观察人点击“安全帽检测”；选择记录中的模型、输入和profile，再触摸开始。先用回放，真实相机短采确认后才选实际节点。记录完整header、画面、框和状态是否可见，横竖屏及列表是否可读；触摸停止后等待工作线程退出，确认下拉框再可更换。对源过期/故障/停止，观察旧画面隐藏与不可用提示，恢复须出现新鲜结果。App按钮操作与下面CLI的q/p/s分别验收。

在WiFi页检查列表滚动、SSID选择和屏幕键盘字母/数字/大小写/符号/空格/退格，密码默认遮掩；不把口令拍进照片或资料。保存观察人、时间和完整物理屏照片/授权录像。自动`screenRoot`抓图可能不含顶部header，只证明该内容区域渲染，不证明人工触摸、整屏或持续可见；Qt实际displayFPS没有测量时保持null。

**独立供电分支。** 先核对板卡与屏幕使用的独立电源型号、额定参数和正确连接方式。正常关闭App并确认清理后，按设备流程断开用于更新/调试的电脑数据连接，保留独立电源；不要拔掉唯一供电来代替这个检查。由观察人从板屏图标重新启动本地模型/输入，记录USB角色、电脑是否仍连接、供电/连接照片、启动与检测结果。首次冷启动另留记录。SSH或隔离网络probe仍在线不能证明无电脑独立操作。

**CLI分支。**

在实际图形会话中去掉`--no-display`，记录屏幕型号/尺寸/分辨率、Wayland显示环境和图像是否可见。当前已归档Qt环境为`XDG_RUNTIME_DIR=/var/run`、`WAYLAND_DISPLAY=wayland-0`、`QT_QPA_PLATFORM=wayland`，须以现场实际环境为准；不能因设置相同变量就认定显示通过。

人工确认画面、对应框、原帧编号、未戴帽横幅，以及源故障/过期后的不可用提示。q/ESC退出、p暂停/恢复、s只保存新鲜结果。保留现场照片或授权录像和观察人记录；窗口create/imshow退出0只是API证据。

音频前核对声卡、输出设备、音量、`aplay`和`/oem/alarm.wav`是否实际存在。运行时加`--alarm-beep --audio-timeout 3`，记录听见时间、观察人、报警事件与audio_failure。当前没有`--audio-file`；缺默认文件不能假写“报警响了”。前期默认文件/声卡如需改变应另行保留设备配置记录，当前模板不修改系统文件。空检测、过期和故障期间不得继续以旧结果触发音频。

## 7 Web与手机

### 7.1 原生WiFi的人工连接验收

先记录原网络SSID或私有标识、关联状态、IP、接口及原网络选择/启用状态，确认有权使用目标开放/WPA2个人网络。由用户进入WiFi页主动扫描，等待默认整体20秒预算；单条控制命令仍是2秒。v3已有列表/键盘自动渲染证据，真实认证/地址/保存/失败恢复仍未验收；扫描不自动连接。失败结束后检查实际环境再手动重试，每次失败保留。

选择支持的SSID，输入密码或按开放网络规则留空，按需要明确勾选保存，再点击连接。分别记录目标SSID匹配、认证完成、DHCP可用地址、保存成功与否；已有网络COMPLETED或扫描列表出现不能替代这些条件。切换网络可能使现有SSH断开，观察应在板屏继续，之后按实际新IP排障；密码、派生PSK和App私有token不进入现场记录。

单独测试一次失败连接，记录本次新建网络清理、原选择和原启用状态恢复，以及地址/路由/DNS是否确有恢复证据。恢复配置不等于恢复全部网络状态；无法证明时标未评或失败，不删除原网络清单补成功。检测在无外网时仍应本地可用，实际供电与操作依旧由上一节人工验证。

### 7.2 CLI Web与手机观察

先用127.0.0.1绑定和SSH转发验证宿主浏览器，再为同局域网手机显式绑定0.0.0.0。保留此次实际IP、端口、浏览器/系统版本，不把凭据写入资料。

```powershell
ssh rk "cd /userdata/helmet-validation/NEW_FIELD_RUN/src && python3 helmet_realtime.py --model ../models/helmet_416x416.rknn --source /dev/videoX --cam-w 640 --cam-h 480 --conf 0.25 --nms 0.45 --skip 0 --result-ttl 1 --no-display --duration 180 --web-host 0.0.0.0 --web-port 8080 --save-dir ../results/web-snapshots --save-interval 30 --jsonl ../results/web.frames.jsonl --session-json ../results/web.session.json"
```

手机在同网访问`http://实际板端IP:8080/`；页面使用`/status.json`和`/stream.mjpg`。分别检查状态字段、实际画面、框/横幅、断开/过期隐藏、恢复新图，不以status HTTP200替代真实浏览器呈现。当前页面依赖持续MJPEG的新load行为，若一直隐藏或报错，保存DOM状态/请求和截图，判为未通过该浏览器，不能只刷新到一次成功后删除失败。

同一会话记录JPEG/MJPEG请求次数、HTTP状态、观察频率和连接数，以便解释Web负载。手机与板端窗口是两个接受条件，宿主LAN预览不能转记为手机已验。

## 8 事件切片和组合长跑

单独冻结一个完整配置。需要录像时添加`--clip-dir ../results/clips --clip-pre 5 --clip-post 5 --clip-fps 10 --clip-encoder mpp`，先验证真实H.264、帧数/时长、前后窗口连续覆盖、masked和提前停止。若使用opencv，明确实际容器/codec，不能改称MPP。编码可重复有效帧，编码10 FPS不等于独立检测10 FPS。

组合长跑包括哪些输出必须写进记录：摄像头、板屏、Web连接负载、音频、截图和一种编码模式。每轮仅串行使用NPU；不要把Pipeline轻回调回放时延归为所有输出并发时延。CLI记录完整日志、资源sidecar、CPU/RSS/温度/NPU频率、磁盘余量、失败与恢复、退出码和governor前后值；正常App没有默认完整逐帧日志，需明确实际有界遥测和外部观察负载，不补造逐帧证据。

记录active起止、session elapsed与FPS分母；状态/HTTP观察只有时间上下界时，按对应区间计算保守吞吐。OpenCV的displayed计数、Qt可见采样比例、真实显示FPS分开，采样不能证明全程持续可见。资源按launcher/service/Qt/observer或CLI进程分别保存PID/start token、RSS首末峰、CPU/线程/FD与原始时序，预先确定描述窗口和接受条件。共享RSS不相加称唯一物理内存；末期抓图/收尾与运行阶段分别标注，不用负endpoint隐藏正OLS趋势。无预设泄漏判据时memory acceptance保持未验。

正常launcher的exit.json及私有材料删除证明本次生命周期；须同时确认launcher/service/Qt终态与启动锁释放。当前正常路径没有独立SDK release收据，不能填写direct SDK released=true，也不能用较早私有runner收据补过。原11月14日API长跑directfalse和较新v2私有验证组合directtrue继续各自解释。

## 9 业务事件标注与指标

使用[event-annotations-template.json](event-annotations-template.json)。模板是未标注、未评估的空实例，不是已执行评价器；本轮没有新增评价算法。先在看模型输出前冻结事件定义、标注范围、时间同步、匹配规则、分母和阈值，再人工标注原始视频，不以检测框自动生成GT。

当前没有身份跟踪，建议初始事件单位为“该source session画面中可见至少一个裸头的连续区间”。不要把全身person或头部遮挡不清强行标裸头；一个session不同人的连续裸头可能属于同一画面事件，不宣称按人员召回。正区间、确定负区间和无法标注的source不可用区间分开；每个已标注时段要求互斥覆盖。短事件保留并按持续时间分层，不因报警dwell而删除短事件。

模板给出待预注册的规则：GT为半开区间`[start,end)`，报警逻辑触发时间须经有效输出与source时间轴校准后匹配；同一GT首次匹配算检出，后续报警单列重复，不增加召回。标注完整的source可用负区间内报警算误报警；位于未标注或source不可用区间的报警单列不可评，不静默当TP/TN。

误报警率主分母为人工已完整标注、source图像可判读的全部观察秒数/3600，包含正负区间；系统检测故障时长单列，不从该主分母或GT召回分母删除来改善成绩。另报负区间每小时误报警率和系统可用比例，名称和分母保持明确。source根本无图/无法判读的区间不属于可标注观察时间，跨这些缺口的GT事件按预先规则拆分或标不可评，保留排除清单。

事件召回=至少一次有效匹配的可评GT事件数/全部可评GT事件数；系统故障导致未触发的完整GT仍算漏报。首次报警延迟=首次有效匹配报警时刻−GT起点；仅对检出事件报中位数/p95/p99，同时报漏报总数和覆盖，不能用有限延迟掩盖漏报。没有GT则召回为null，没有可评观察时长则每小时指标为null。

默认可测的是应用报警逻辑触发，不能等同音频可听或屏幕呈现延迟。逐帧日志提供`output_at`、`callback_finished_at`、`alarm_triggered`和有效标志；真实发出报警的event callback若由runner另记monotonic，应保留该原日志。CLI没有`--events`参数，不能引用不存在的日志。截图保存时刻、文件名wall time、frame ID或请求回放FPS不能直接当视频PTS；时间轴同步方法和误差必须先核对，缺映射则延迟保持未评。

## 10 保存和交接

每轮保留模板填充副本、参数命令、设备枚举、图像/录像/标注SHA、场景/session来源与许可、原始frame和resource记录、HTTP/人工观察、事件产物、退出/清理/governor读回。JSON中的测量值初始null，实际失败写failed及原因，未测写not_tested，不能填0假装测量。

现场结果只提升本轮确实覆盖的接受条件。新采集素材若要用于独立精度，须证明来源在模型冻结后新取得、无复用训练素材、按真实session分组；更换第三个公共图片集或删除共有照片不自动建立独立性。学校85%指标口径和最终配置仍需明确。论文结构可参考[章节与证据映射](论文结构与证据映射.md)。

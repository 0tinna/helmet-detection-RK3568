## 1. 项目概述

### 1.1 课题背景

建筑施工、能源电力、轨道交通等现场对安全帽佩戴监管需求高，传统人工巡检实时性差、效率低。基于深度学习的目标检测可自动识别人员与安全帽状态；以 RK3568 为代表的嵌入式 AI 平台具备本地推理能力，可减少对云端依赖，兼具响应快、部署灵活、隐私保护等优势。

### 1.2 研究目标

设计并实现一套运行于 RK3568 的轻量化安全帽佩戴检测系统：摄像头采集 → 轻量化模型推理 → 结果标注 → 未佩戴提示。

### 1.3 量化指标（开题报告）

| 指标 | 要求 |
|---|---|
| 检测准确率 | ≥ 85% |
| 推理速度 | ≥ 10 FPS |
| 输出内容 | 检测框、类别、置信度 |
| 功能 | 未佩戴安全帽提示 |

### 1.4 技术路线

```
数据集构建 → YOLOv8n/YOLOv5n 训练 → ONNX 导出
          → RKNN-Toolkit2 量化转换 → RK3568 NPU 部署
          → 摄像头实时采集 → 检测 → 显示与报警
```

## 3. 系统总体设计（论文第 3 章素材）

### 3.1 总体架构

```
┌──────────────────── 感知层 ────────────────────┐
│  USB UVC 摄像头（百立创，免驱动，USB Type-A）      │
│  → /dev/video10（预计）→ YUY2 / MJPEG 帧          │
└───────────────────────┬─────────────────────────┘
                        ↓
┌──────────────────── 预处理层 ───────────────────┐
│  cv2.VideoCapture / GStreamer v4l2src            │
│  → letterbox 等比缩放 + 灰边填充 → 640×640 RGB    │
│  → NHWC uint8 张量（模型转换时已固化 /255）       │
└───────────────────────┬─────────────────────────┘
                        ↓
┌──────────────────── 推理层 ─────────────────────┐
│  RKNNLite → librknnrt 2.3.2 → RKNPU（0.8 TOPS）  │
│  模型：YOLOv5/v8n int8 .rknn（640×640）           │
│  输出：3 个检测头 (1,3,H,W,7)                     │
└───────────────────────┬─────────────────────────┘
                        ↓
┌──────────────────── 后处理层 ───────────────────┐
│  Sigmoid → 网格/锚框解码 → 置信度筛选 → 类别 NMS  │
│  → 反 letterbox 坐标还原                          │
└───────────────────────┬─────────────────────────┘
                        ↓
┌──────────────────── 应用层 ─────────────────────┐
│  业务判定：person 框内无 hat → 判定「未佩戴」      │
│  → 画框/类别/置信度 → kmssink 上屏 / 编码推流     │
│  → 未佩戴提示（UI 红框、蜂鸣器或语音播报）        │
└─────────────────────────────────────────────────┘
```

### 3.2 模块划分

| 模块 | 职责 | 现状 |
|---|---|---|
| M1 图像采集 | 从 UVC 摄像头取帧 | 待实现 |
| M2 预处理 | letterbox、色彩空间转换 | ✅ 单图版已实现 |
| M3 NPU 推理 | 加载 RKNN、执行推理 | ✅ 已实现 |
| M4 后处理 | 解码、NMS、坐标还原 | ✅ 已实现 |
| M5 业务判定 | 佩戴/未佩戴逻辑 | ✅ 逻辑已验证，代码待封装 |
| M6 结果显示 | 画框、类别、置信度 | ✅ 单图版已实现 |
| M7 报警提示 | 声/光/UI 告警 | 待实现 |
| M8 性能统计 | FPS、耗时、资源占用 | ✅ 已实现 |

### 3.3 未佩戴判定逻辑

模型输出 `person`（人/头部）与 `hat`（安全帽）两类，二者需**组合判定**：

```
对每个 person 框 P：
    若存在 hat 框 H，使 IoU(P, H) > θ 或 H 中心落在 P 上部区域
        → 判定「已佩戴」
    否则
        → 判定「未佩戴」，触发提示
```

θ 与人头/安全帽的相对位置阈值需在实际数据集上调参，这是后续实验内容之一。

## 4. 已完成的关键实现（论文第 4 章素材）

### 4.1 开发板环境搭建

- **接入通道（当前主用 SSH）**：`ssh rk`（`root@192.168.1.3`，公钥免密，单次约 0.3 s），支持 `scp` 传文件。
- 串口兜底通道：`COM6 @ 1500000 8N1`，封装为 `rk.cmd` 一条命令下发，仅在板子离线/IP 变化时使用。
  - 解决了板端每次提示符前发送 `ESC[6n` 终端探针并阻塞等待应答、吞掉命令字节的问题（引擎主动回 `ESC[24;80R`）。
- 无线网络：解决 `rfkill1 soft=1` 软件阻断与 connman 独占 wlan0 导致的扫描 busy；部署开机自启脚本。
- SSH 免密：公钥写入 `/root/.ssh/authorized_keys`（目录 700 / 文件 600）。

### 4.2 NPU 推理环境

```sh
pip3 install -i https://pypi.tuna.tsinghua.edu.cn/simple rknn-toolkit-lite2
```

实测：安装 `rknn-toolkit-lite2 2.5.0`（cp310 aarch64），与板端 `librknnrt 2.3.2` 兼容；`from rknnlite.api import RKNNLite` 导入成功。

### 4.3 模型结构（实测读出）

| 项 | 值 |
|---|---|
| 模型文件 | `helmet-640-640.rknn`（7.8 MB） |
| 结构 | YOLOv5s，int8 量化，2 类 |
| 目标平台 | rk3566（与 rk3568 同属 RKNPU2，可直接运行） |
| 转换工具链 | rknn-toolkit 1.4.0（2022 年，版本较老） |
| 输入 | 640×640×3，NHWC uint8 |
| 输出 | `(1,3,80,80,7)`、`(1,3,40,40,7)`、`(1,3,20,20,7)` |
| 输出语义 | 3 = anchor 数；7 = 4 框 + 1 obj + 2 类 |
| 类别 | `("person", "hat")` |

### 4.4 预处理

等比缩放 + 灰边填充（letterbox）到 640×640，BGR→RGB，扩展 batch 维为 NHWC uint8。
反变换时**仅左上角坐标减 padding 偏移**，宽高只除以缩放比。

### 4.5 后处理（YOLOv5 解码）

```
p = sigmoid(output)
cx = (p[...,0]*2 - 0.5 + grid_x) * stride
cy = (p[...,1]*2 - 0.5 + grid_y) * stride
bw = (p[...,2]*2)^2 * anchor_w
bh = (p[...,3]*2)^2 * anchor_h
conf = p[...,4] * max(p[...,5:])
```

三尺度 stride = 8 / 16 / 32，锚框采用 YOLOv5 默认 9 组；随后按类别做 `cv2.dnn.NMSBoxes`（`CONF_TH=0.25`，`NMS_TH=0.45`）。

### 4.6 调试过程中定位的 4 类错误（可写入论文「系统调试」小节）

1. 输出张量轴 1 是 anchor 而非 batch；因 H=W 为正方形，轴序写反不报错但结果错误。
2. 类别顺序误写为 `helmet/head`，实际为 `person/hat`。
3. `cv2.dnn.NMSBoxes` 接收 `xywh`，而画框需要 `xyxy`；混淆会导致框横跨全图。
4. letterbox 反变换对宽高误减 padding。

此外，首次调用 `cv2.dnn.NMSBoxes` 含初始化开销（约 40 ms），性能测量须多次取平均。

## 5. 实验结果（截至 2026-11-12）

### 5.1 功能验证

测试图：工地 8 人场景 `1.jpg`（1280×960），输出 `out1.jpg`。

| 结果 | 数值 |
|---|---|
| `hat` 检测框 | 8 个，置信度 0.81 ~ 0.92 |
| `person` 检测框 | 1 个，置信度 0.53 |
| 目视核验 | 8 顶红色安全帽均被准确框出；唯一未戴帽的白衣男子被识别为 `person` |

**结论**：检测框位置、类别、置信度正确，佩戴判定逻辑自洽。

> 注：以上为**单张图片的定性验证**，不是准确率评测。85% 指标仍需自建测试集并计算 mAP 后判定。

### 5.2 性能实测（NPU 锁定 performance 档，900 MHz）

| 阶段 | 耗时 | 等效帧率 |
|---|---|---|
| NPU 推理（640×640 int8） | 116.26 ms | 8.6 FPS |
| 后处理（decode + NMS，10 次平均） | 22.65 ms | — |
| **端到端**（预处理 + 推理 + 后处理） | **141.27 ms** | **7.1 FPS** |

### 5.3 与指标的差距分析

| 指标 | 要求 | 实测 | 差距 | 主因 |
|---|---|---|---|---|
| 推理速度 | ≥ 10 FPS | 7.1 FPS（端到端） | 约 −29% | 模型由 1.4.0 老工具链转换，NPU 推理占 82% 耗时 |
| 准确率 | ≥ 85% | 未评测 | — | 无自建测试集 |

**性能瓶颈定位**：后处理仅占 16%，优化空间有限；核心在推理侧。

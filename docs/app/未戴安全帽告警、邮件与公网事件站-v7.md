# 未戴安全帽告警、邮件与公网事件站 v7

**当前状态：`20261124-v7-r1` 软件候选版。** 本版已完成主机侧轨迹去重、证据落盘、SMTP 队列、鉴权事件站和常驻生命周期集成测试，但尚未完成开发板物理摄像头、真实 SMTP、路由器端口转发、手机蜂窝网络和外网访问验收。因此，主机测试通过不能替代现场交付结论。

## 1. 功能边界

本版只把模型输出中的 `person` 作为“未戴安全帽的头部”，不会把它解释为完整人体或真实身份。`hat` 表示检测到佩戴安全帽的头部。模型、类别顺序、`conf=0.35`、`NMS=0.45`、`skip=0`、TTL 1 秒、Pipeline 后处理、原报警音和 Qt 双 Image 行为均保持不变。

新增链路如下：

```text
新鲜检测包 + 已编码 JPEG
        |
        v
轻量 IoU 轨迹表（IoU 0.30，连续 2 帧确认，消失宽限 2 秒）
        |
        +--> 新轨迹确认：保存带检测框的 JPEG + JSON
        |
        +--> 5 秒窗口聚合：异步发送到 230010044@mail.szpu.edu.cn
        |
        +--> 鉴权只读事件站：8092
```

同一轨迹持续在画面中只保存一次。第二个或后续未戴帽人员形成新轨迹时，分别新增事件。人员离开超过 2 秒后再次进入会作为新轨迹处理。摄像头断流、结果超过 1 秒 TTL、检测停止、source epoch 变化、运行代际变化或 JPEG 编码失败时，不生成新事件。

轨迹 ID 仅用于本次运行内的事件去重，不代表生物识别或真实人员身份。人员遮挡超过宽限时间后重入，可能形成新的合规事件；这是当前轻量跟踪器的已知限制。

## 2. 端口和网络边界

| 端口 | 用途 | 鉴权 | 公网暴露 |
| --- | --- | --- | --- |
| `8091` | v6 既有的局域网实时预览 | 无 | **禁止** |
| `8092` | v7 已保存事件、事件图片和状态 | 30 天 HMAC 邀请令牌与 HttpOnly Cookie | 仅在路由器明确转发时可用 |

`8092` 只读取 `results/helmet-events/` 中已经落盘的事件，不提供实时帧、MJPEG、检测启动、WiFi、退出或其他控制接口。实时预览继续只用于可信局域网。

`ifconfig.me` 能返回地址，只证明开发板具备出站网络。它不能证明该地址是可入站访问的公网 IPv4，也不能证明路由器 NAT、运营商 CGNAT、防火墙或端口转发已经可用。

## 3. 新根整体部署

目标版本：

```text
20261124-v7-r1
tag: native-app-v7-r1
root: /userdata/helmet-validation/20261124-native-app-v7-r1
```

部署要求：

1. 先通过 App 完整退出旧实例，确认检测进程、Qt、`8091`、`8092`、SMTP worker 和资源锁均已结束。
2. 校验候选 ZIP SHA256，并对照 `manifest.json` 逐文件核验。
3. 解压完整 ZIP 到新的隔离根，不向旧版本根逐个补文件。
4. 不得改写或覆盖 v1-v6 的 ZIP、manifest、实验记录和 tag。
5. 完成整根校验后再迁移本项目拥有的两个图标入口；厂商 `systemui` 重启由人工决定。

发布包包含 `mail.example.json`，不包含真实的 `mail.json`、`public-access.key`、`app-state/`、事件照片或 SMTP 凭据。
包内 `src/app/deploy.ps1` 已纳入四个告警模块和模板，`install.py` 会把它们纳入安装前完整性检查；仍应优先使用完整 ZIP 到新隔离根部署。

## 4. 配置邮件

在板端新根下创建私有配置：

```sh
cd /userdata/helmet-validation/20261124-native-app-v7-r1
mkdir -p app-state
cp src/app/mail.example.json app-state/mail.json
chmod 700 app-state
chmod 600 app-state/mail.json
vi app-state/mail.json
```

必须替换以下字段：

```json
{
  "enabled": true,
  "smtp_host": "YOUR_SMTP_HOST",
  "smtp_port": 465,
  "security": "ssl",
  "username": "YOUR_SENDER_ACCOUNT",
  "password": "YOUR_SMTP_AUTH_CODE",
  "sender": "YOUR_SENDER_ACCOUNT",
  "recipient": "230010044@mail.szpu.edu.cn",
  "timeout_seconds": 8,
  "batch_seconds": 5
}
```

`security` 只接受 `ssl`、`starttls` 或 `none`。实际认证方式由邮件服务商决定，常见组合是 `465 + ssl` 或 `587 + starttls`。

不得把真实 `mail.json` 放进 Git、截图、实验 JSON、日志或发布 ZIP。不要把邮箱登录密码与 SMTP 授权码混用；学校邮箱是否开放 SMTP、允许的端口和发信白名单需要以邮件服务方配置为准。

配置文件不存在时，检测和事件保存仍继续，告警状态为 `not_configured`。配置格式错误或权限不安全时，服务启动应失败并保留私有日志供排查，不能假装邮件可用。

## 5. 公网事件入口

首次以常驻模式启动后，板端自动创建：

```text
app-state/public-access.key
```

该文件权限为 `0600`，至少包含 256 bit 随机值。Linux 板端会拒绝组用户或其他用户可读写的既有密钥文件。事件站默认监听 `0.0.0.0:8092`。启动后入口为：

```text
http://开发板IP:8092/
```

根页面不包含事件数据，适合检查服务是否运行。邮件中的链接采用：

```text
http://动态公网IP:8092/alerts?access=HMAC邀请令牌
```

访问邀请链接成功后，服务设置 `HttpOnly; SameSite=Strict` Cookie 并跳转到 `/events`，避免令牌持续留在浏览器地址栏。默认邀请有效期为 30 天。旧链接失效后，从新告警邮件获取新链接。

路由器需要把公网 TCP `8092` 转发到开发板 `8092`。如果运营商使用 CGNAT，仅在路由器上做端口转发可能仍无法从手机蜂窝网络访问；此时应使用学校允许的跳板、VPN、Tailscale/WireGuard 或受控 HTTPS 反向代理。

删除或轮换 `public-access.key` 会让所有旧邀请和 Cookie 失效。轮换前先完整退出 App；轮换后重新启动，并从新邮件取得入口。

原始 HTTP 适合课程演示、受控网络或临时验收。长期公网运行应在 HTTPS 反向代理或 VPN 后使用，避免照片和访问 Cookie 以明文传输。

## 6. 存储与清理

默认策略：

| 项目 | 默认值 |
| --- | --- |
| 事件保留 | 7 天 |
| 事件文件总上限 | 256 MiB |
| 最大事件数 | 5000 |
| 磁盘最低余量 | 128 MiB |
| 清理时机 | 启动时和每小时 |

目录结构：

```text
results/helmet-events/YYYY/MM/DD/
  <event-id>.jpg
  <event-id>.json
```

图片和 JSON 使用同目录临时文件、`flush`、`fsync` 和 `os.replace()` 原子发布。损坏 JSON、越界路径、符号链接和不存在的事件 ID 不会展示为正常证据。磁盘低于安全余量时停止新增事件并保留已有证据。

`public_ip` 仅在能够可靠取得时记录。若发信时公网地址查询失败，邮件正文会明确写出“未知”或“可能已变化”，不会伪造地址。

## 7. 启动和检查

正常图标入口仍走常驻生命周期。常驻服务固定启用事件功能：

```text
--alert-port 8092
```

one-shot 验证模式固定关闭事件功能：

```text
--alert-port 0
```

这样不会让验证任务意外发送真实邮件或占用公网事件端口。

只看本机健康状态：

```sh
curl -fsS http://127.0.0.1:8092/healthz
```

正常返回：

```text
ok
```

根入口：

```text
http://板端IP:8092/
```

事件数据必须使用带有效邀请令牌的邮件链接或已认证 Cookie。不要通过公开日志、截图或 shell 历史保存完整邀请链接。

状态回执包含：

- `alert_viewer_alive`
- `alert_port`
- `alert_stopped`
- `mail.configured`
- `mail.state`
- `mail.last_result`
- `mail.pending_batches`
- `mail.dropped_batches`

SMTP 或事件站故障不会把检测状态改成 fault；但关闭未确认时不得报告 `cleanup_completed=true`。

## 8. 排障顺序

1. `8092` 端口被占用：新服务必须启动失败；不要静默改端口或继续运行假的就绪状态。
2. 能保存照片但收不到邮件：检查 `app-state/mail.json`、SMTP 端口/安全模式、授权码、发信白名单和 `mail.state`。
3. 邮件有链接但局域网能开、蜂窝网络不能开：检查公网 IP 类型、路由器转发、防火墙和 CGNAT。
4. 公网 IP 改变后旧链接失效：从新告警邮件重新获取链接；长期部署应改用稳定域名或 VPN。
5. `/events` 返回 403：使用新的完整邀请链接，或重新从告警邮件打开入口。
6. 摄像头断流后仍显示检测中：本版必须依赖原 `valid/source_epoch/expires_at` 校验抑制旧帧；现场仍需执行拔线 TTL 验收。
7. 同一人重复告警：记录进入/离开时间、Frame ID 和遮挡时长，区分真实重入、短漏检和跟踪抖动，不能只凭邮件数量下结论。

## 9. 本版验收范围

已完成的软件证据：

- 轨迹去重、多人后进入、短漏检、重入、代际/epoch 重置。
- JPEG/JSON 原子落盘、保留期限、字节与数量配额、损坏文件和路径安全。
- SSL/STARTTLS、5 秒聚合、附件、3 次重试、有界队列和脱敏状态。
- 8092 邀请/Cookie 鉴权、分页、日期筛选、只读边界、安全响应头和客户端上限。
- AlertHub 故障隔离、代际切换后的旧 generation 拒绝、启动时与每小时保留清理、可重试关闭、常驻 `8092`、one-shot 禁用、启动失败和真实关闭回执。
- 事件页读取真实检测状态和缓存的动态公网地址；初次状态查询最多每分钟刷新一次公网地址，避免 UI 轮询反复访问外部服务。
- 损坏但语法合法的非对象事件 JSON 会被隔离；SMTP 认证异常不会杀死发信 worker，聚合邮件的“人数”按运行代际、source epoch 和轨迹 ID 去重。
- 发布包包含告警模块与模板，排除 live secret，记录五文件 identity 和告警功能 identity。

尚未由本文件证明：

- 物理 USB 摄像头下的轨迹稳定性、多人重叠和拔线 TTL。
- Qt 窗口隐藏后持续检测、事件保存和邮件发送。
- 真实 SMTP 服务器收件、延迟和重试行为。
- 路由器 `8092` 转发、公网动态 IP 和手机蜂窝网络访问。
- 180 秒物理长跑、无进程堆积、完整退出和端口释放。

这些项目必须在开发板、真实凭据和外部网络可用后生成独立实验报告。未执行项保持 `not-run`，不得用主机模拟或其他版本结果填补。

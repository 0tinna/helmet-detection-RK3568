# 未戴安全帽告警、邮件与内网事件站 v7-r2

**当前状态：`20261124-v7-r2` 软件与板端核心链路候选版。**

本版保留 v7-r1 的未戴帽轨迹去重、照片证据、SMTP 聚合告警、鉴权历史事件页和
自动清理，同时彻底移除动态公网 IP 查询与公网访问设计。事件站只面向与开发板
处于同一 Wi-Fi/局域网的可信设备，固定使用 `8092`，不提供路由器或手机热点
端口转发方案。

ATK-DLRK3568 已完成回放事件、鉴权 `8092` 页面、程序化常驻隐藏/唤回、180 秒
物理摄像头长跑、UVC sysfs 断流 TTL 和完整退出。真实未戴帽多人/重入、
人工拔线和板屏观察、真实 SMTP 收件、同网实体手机和图标人工点击仍须独立验收。

## 1. 功能边界

模型类别和阈值保持不变：

- `person` 表示未戴安全帽的头部。
- `hat` 表示戴有安全帽的头部。
- conf `0.35`、NMS `0.45`、skip `0`、TTL `1 s`。

新增链路为：

```text
新鲜检测包 + 已编码 JPEG
        |
        v
轻量 IoU 轨迹去重
        |
        +--> 新未戴帽轨迹：原子保存 JPEG + JSON
        |
        +--> 5 秒窗口聚合 SMTP 告警
        |
        +--> 同一局域网事件站：http://开发板内网IP:8092/
```

同一轨迹持续停留只保存一次；后续进入画面的不同未戴帽轨迹分别形成事件。
轨迹 ID 只用于单次运行内去重，不代表身份识别。

## 2. 网络与端口

| 端口 | 用途 | 默认监听 | 访问边界 |
| --- | --- | --- | --- |
| `8091` | 实时只读预览 | `0.0.0.0` | 仅可信局域网，禁止转发 |
| `8092` | 已保存事件、照片与状态 | `0.0.0.0` | 仅 RFC1918 私网或回环来源 |

`8092` 只读取 `results/helmet-events/` 中已经落盘的事件，不提供实时帧、
MJPEG、检测启动、Wi-Fi、退出或其他控制接口。

本版不再查询 `ifconfig.me` 或任何外部地址服务，不记录、返回或展示公网 IP。
邮件中的查看地址来自开发板当前默认路由对应的私网 IPv4，并使用 `8092` 端口。
路由器端口映射、手机热点转发、CGNAT、NAT 穿透和蜂窝网络访问不属于本版功能。

事件站在 HTTP 入口额外拒绝直接来自公网、CGNAT 和无法解析地址的客户端。
如果路由器先把公网连接 NAT 成私网地址再转发到板端，应用层无法识别原始来源，
因此必须由 AP/路由器保持“不配置端口映射”，并配合 Wi-Fi 密码、主机防火墙和
可信局域网管理。这个客户端地址检查只是附加防线，不是公网隔离的替代品。

## 4. 邮件告警

在板端新根下创建私有配置：

```sh
cd /userdata/helmet-validation/20261124-native-app-v7-r2
mkdir -p app-state
cp src/app/mail.example.json app-state/mail.json
chmod 700 app-state
chmod 600 app-state/mail.json
vi app-state/mail.json
```

必须替换以下字段：

```json
{
  "enabled": true,
  "smtp_host": "YOUR_SMTP_HOST",
  "smtp_port": 465,
  "security": "ssl",
  "username": "YOUR_SENDER_ACCOUNT",
  "password": "YOUR_SMTP_AUTH_CODE",
  "sender": "YOUR_SENDER_ACCOUNT",
  "recipient": "230010044@mail.szpu.edu.cn",
  "timeout_seconds": 8,
  "batch_seconds": 5
}
```

`security` 只接受 `ssl`、`starttls` 或 `none`。常见组合为 `465 + ssl`
或 `587 + starttls`。不得把真实 `mail.json`、授权码或访问密钥提交到 Git、
截图、日志或发布 ZIP。

配置完成后执行一次同步自检：

```sh
python3 src/app/mail_probe.py --root /userdata/helmet-validation/20261124-native-app-v7-r2
```

成功输出：

```json
{"ok": true, "sent": true, "recipient": "230010044@mail.szpu.edu.cn", "lan_address_available": true}
```

失败统一返回 `mail_probe_failed`，不会输出 SMTP 响应正文、密码或授权码。
自检邮件不是检测告警，不包含事件照片。

常规告警正文保持简短，包含发生时间、本批人数、本批事件数、内网查看地址和要求
手机与开发板连接同一 Wi-Fi/局域网的提示，并附第一张事件 JPEG。

## 5. 内网事件站

首次以常驻模式启动后，板端自动创建：

```text
app-state/event-access.key
```

该文件权限为 `0600`，至少包含 256 bit 随机值。Linux 板端会拒绝组用户或
其他用户可读写的既有密钥文件。

本机检查：

```sh
curl -fsS http://127.0.0.1:8092/healthz
```

正常返回：

```text
ok
```

同一局域网访问：

```text
http://开发板当前内网IP:8092/
```

根页面只提供访问说明。事件数据必须使用告警邮件中的邀请链接：

```text
http://开发板当前内网IP:8092/alerts?access=HMAC邀请令牌
```

访问成功后服务设置 `HttpOnly; SameSite=Strict` Cookie 并跳转到 `/events`。
邀请默认有效 30 天；旧邀请失效后，从新告警邮件获取新链接。

页面继续采用赛博危险/安全主题，展示事件照片、发生时间、事件 ID、帧号、
检测状态、邮件状态和存储占用。公网 IP 卡片已删除，改为 LAN 在线/离线状态。

删除或轮换 `event-access.key` 会让所有旧邀请和 Cookie 失效。轮换前先完整
退出 App；轮换后重新启动，并从新告警邮件取得入口。

## 6. 存储与清理

| 项目 | 默认值 |
| --- | --- |
| 事件保留 | 7 天 |
| 事件文件总上限 | 256 MiB |
| 最大事件数 | 5000 |
| 磁盘最低余量 | 128 MiB |
| 清理时机 | 启动时和每小时 |

目录结构：

```text
results/helmet-events/YYYY/MM/DD/
  <event-id>.jpg
  <event-id>.json
```

图片和 JSON 使用同目录临时文件、`flush`、`fsync` 和 `os.replace()` 原子发布。
磁盘低于安全余量时停止新增事件并保留已有证据。

## 7. 启动和状态

常驻服务固定启用内网事件站：

```text
--alert-port 8092
```

one-shot 验证模式固定关闭事件功能：

```text
--alert-port 0
```

因此验证任务不会意外发送真实邮件或占用事件端口。

状态回执包含：

- `alert_viewer_alive`
- `alert_port`
- `alert_stopped`
- `mail.configured`
- `mail.state`
- `mail.last_result`
- `mail.pending_batches`
- `mail.dropped_batches`

SMTP 或事件站故障不会把检测状态改成 fault；关闭未确认时不得报告
`cleanup_completed=true`。

## 8. 排障

1. `8092` 被占用：新服务必须启动失败，不静默改端口。
2. 能保存照片但收不到邮件：先执行 `mail_probe.py`，再检查 SMTP 白名单。
3. 局域网设备打不开：确认手机和开发板在同一子网，且 AP 未启用客户端隔离。
4. `/events` 返回 403：使用同一内网的新邀请链接，或确认客户端来源不是公网地址。
5. 邮件未给出地址：检查开发板默认路由和私网 IPv4；本版不会改用公网 IP。
6. 公网客户端被拒：这是预期行为，本版不支持公网端口访问。

- v7-r2 整包版本、根路径、五文件 identity、告警 identity 和 secret 排除。
- Pipeline 真实 NumPy 检测框的事件跟踪回归；修复前画面有红框但事件表为空。
- 板端归档回放图生成 8 条裸头轨迹、JPEG/JSON 与第 2 帧事件。

# 离线更新与图标安装

更新日期 2026年11月15日

本流程针对已经安装兼容Linux、Python、OpenCV、NumPy、RKNNLite、Qt/qmlscene和wpa_supplicant的RK3568。它覆盖应用文件复制、原生入口注册及更新，不是空白板卡的OS与全部依赖离线安装。日常使用板屏App不需要电脑；更新时可临时使用U盘，或在用户手动连接WiFi后由主机复制文件。

v2修复部署根为`/userdata/helmet-validation/20261115-native-app-v2`，打包前v1历史根为`/userdata/helmet-validation/20261114-native-app`。实际图标入口版本以外部发布/安装迁移记录为准，新根与ZIP不会自动切入口。保留旧版、模型、结果、网络配置和备份，不覆盖运行中代码；步骤路径按实际包/挂载点替换。

## 1 先辨认发布包

使用[v2原生包](../../dist/helmet-native-app-20261115-v2.zip)时，复制前按[实际v2发布清单](../experiments/2026-11-15/native-app/bundle-manifest-v2.json)核对ZIP SHA、字节数与内部文件身份；包自身SHA只在外部清单中记录。v2服务修复并发预览丢缓存，SHA `9a2f7454db6fb48ebcf7f5fd301a831817374c2be2fc5c9036af60feb40df1f7`，不是只改包名。

[v1原生包](../../dist/helmet-native-app-20261115.zip)/[v1清单](../experiments/2026-11-15/native-app/bundle-manifest.json)保持39,192,392B/28payload、SHA `22585661da80c449fbf85ba65978ba851c73935819298ee2a5de48907824e679`，包含旧service，不能覆盖或改写为v2。更早CLI final ZIP不含App。各版本均需预装兼容Qt/Linux/RKNN。

发布后先核对包中是否有以下文件，不只看ZIP名字：

```text
src/app/launch.py
src/app/service.py
src/app/wifi.py
src/app/qml/Main.qml
src/app/icons/helmet.svg
src/app/icons/wifi.svg
src/ 共用Pipeline源文件
models/ 已有RKNN模型
input/ 明确回放输入
```

有模型/样图的本地包不自动包含它们的再分发授权；个人板端部署和公开发布是不同动作。保留模型来源说明，未知授权素材不自动传到外部平台。

## 2 通过U盘更新

在有发布包后，将它及SHA/清单复制到U盘。插入板卡USB host接口，使用板卡实际文件管理器确认挂载点、剩余空间和可读文件。不能把固定`/media/usb`当作所有板卡的已验证挂载点。

如板卡允许本地终端，以下为新建更新目录的示意，`ACTUAL_USB_MOUNT`、包名、EXPECTED_SHA及NEW_APP_ROOT均须替换：

```text
sha256sum /ACTUAL_USB_MOUNT/helmet-native-app-20261115-v2.zip
mkdir -p /userdata/helmet-validation/NEW_APP_ROOT
unzip /ACTUAL_USB_MOUNT/helmet-native-app-20261115-v2.zip -d /userdata/helmet-validation/NEW_APP_ROOT
```

先对照发布的SHA，再解压到新根；确认解压结构是新根下的`src/app`而不是又多一层包目录。若系统没有unzip或本地终端，使用现有文件管理器解压/复制已解压目录，不能写成所有板卡都已验证一键安装。拔U盘前完成复制和实际文件核验，App需从/userdata读取，不能运行U盘上的临时文件后宣称拔盘独立。

## 3 通过手动WiFi与SCP更新

先在板屏手动连接所需WiFi，等待关联与DHCP状态。切网可能中断现有SSH，使用实际新IP或已更新别名。不要将首次接入需要电脑与日常检测需要电脑混为一谈：电脑在此仅作为一次文件来源。

主机复制发布包的示意：

```powershell
scp .\dist\helmet-native-app-20261115-v2.zip rk:/userdata/helmet-validation/
ssh rk "sha256sum /userdata/helmet-validation/helmet-native-app-20261115-v2.zip"
```

这些命令仅在新包真实生成后执行。核对SHA和目录结构，再按U盘步骤解压到新的App根。当前checked检测部署入口`helmet/deploy.ps1`的具体复制范围以源码/manifest为准；它此前不是App专用发布流程，不用旧部署成功推断新App文件齐全。

使用SCP需要当时联网和SSH，安装后板屏的本地检测不需要继续连接主机。不得把主机私钥、WiFi密码或运行中App私有令牌放入发布包。

## 4 安装原生入口

App复制/manifest核对齐全后，可运行安装器创建该根的普通desktop入口。以下为v2部署路径示例，并不说明现有厂商入口已切换：

```text
python3 /userdata/helmet-validation/20261115-native-app-v2/src/app/install.py --root /userdata/helmet-validation/20261115-native-app-v2
```

普通安装会在运行用户的`~/.local/share/applications/`创建“安全帽检测”和“Wi-Fi 设置”两个desktop条目。某些标准桌面识别这些文件，但本板厂商主界面使用自己的图标清单，普通desktop注册不能证明厂商图标出现。

针对已探测ATK主界面，用户已要求图标入口；以下是此前v1实际安装命令，保留用于辨认历史入口，不作为自动切v2命令：

```text
python3 /userdata/helmet-validation/20261114-native-app/src/app/install.py --root /userdata/helmet-validation/20261114-native-app --vendor-icons
```

厂商集成只支持探测到的`/opt/ui`与`ATK-DLRK...`主机配置。本轮清单是`/opt/ui/src/ATK-DLRK3568/apk3.cfg`，新增`helmet_app`和`helmet_wifi`两条目；`src/apps/`入口及`src/appicons/`图标链接指向/userdata中的启动文件/原图。实际文件和原始cfg备份留在本轮`vendor-entry/`，安装器输出备份路径。

这是一处用户授权的厂商桌面配置修改，不能写成“系统所有文件未改”。安装器不自动重启桌面或增加后台自启动服务。主界面下次启动才读取新清单，因此安装完成后仍需用户重新加载主界面或下次正常开机观察图标、点击、触摸和窗口。

本轮实际[图标安装日志](../experiments/2026-11-15/native-app/icon-install.log)已归档，配置新增两条目，入口链接指向/userdata包装文件。包装文件将验证参数按原argv转交启动器，不包含密码；这不等于人工已在主界面看到图标或点击成功。

该历史日志属于v1根，实际入口链接及迁移以外部安装/发布记录核对。迁移需明确备份旧链接，仅更新确切App符号链接/desktop目标并保留回退；本手册没有预写v2入口已迁移或通过，不把v1包装器exit0归给v2。

## 5 新版入口与旧版的处理

在新根放置文件不等于现有图标自动切到新根。厂商入口已属于旧安装时，当前安装器会拒绝把别人的/另一根入口链接覆盖为新版；这保护已有入口，但意味着升级切换必须明确处理。

先正常关闭旧App，确认清理完成，记录现有链接目标和cfg备份。由维护者在单一板端shell中核对新旧绝对路径、备份配置后，再仅更新确切App入口链接及desktop Exec目标，或选择继续使用现有稳定版。不要递归删除旧App根、用户结果或整个`/opt/ui`；不要在不了解桌面配置时删除原有条目。当前没有已验证的自动版本切换/回退按钮，本文件不提供泛化删除脚本。

若需要回退厂商cfg，使用安装器输出的实际原始备份，先检查其日期、原内容和目标`apk3.cfg`路径，再恢复该配置并让主界面正常重新加载。撤销仅本App的入口链接前核对其当前目标，保留应用数据。当前命令层自动回滚不是已交付功能，手动回退应保留维护记录。

## 6 先短测，再日常使用

安装文件、入口与权限核对后，在板端已有Wayland会话中可以启动本地窗口：

```text
python3 /userdata/helmet-validation/20261115-native-app-v2/src/app/launch.py --root /userdata/helmet-validation/20261115-native-app-v2 --tab detection
python3 /userdata/helmet-validation/20261115-native-app-v2/src/app/launch.py --root /userdata/helmet-validation/20261115-native-app-v2 --tab wifi
```

不要同时启动两个命令，启动锁只允许一个会话。正常使用不加验证专用`--auto-demo`、`--smoke-seconds`、`--verify-keyboard`；用户点击开始和手动连接。自动8秒demo退出0只是图形/服务短验证，不等于完整触摸、真联网或断USB验收。

最新[native-smoke-4](../experiments/2026-11-15/native-smoke-4/run-verification.json)用v2服务/私有QML验证wrapper直接调用LocalService与DetectionController，未执行launch.py。12秒134检测、11.1230检测/11.0400输出FPS，3次active HTTP200和实际Qt图、直接清理accepted；`thirty_minute_app_passed=false`，只支持该短配置。上面正常launch.py及厂商v2入口需各自实测，不能借用验证器路径宣布通过。

检查本地模型/回放列表、开始/停止、图像对应、故障/TTL、键盘输入和正常退出后，断开用于更新的电脑连接，使用独立电源在板屏点击图标验证。人工记录是否能开启与运行，无电脑条件不能靠SSH仍在线的自动probe证明。真实摄像头接入按[现场验收步骤](../field-validation/摄像头接入与现场验收.md)另测。

# 离线安全帽检测与状态闭环项目阅读导航

更新日期 2026年11月15日

本项目使用现成社区YOLOv5模型，在RK3568上完成安全帽佩戴检测、时效校验、报警留痕和部署评估。当前范围不包含训练、微调、剪枝或蒸馏。第一次了解项目时，先理解系统解决的问题，再阅读代码和原始记录。

板屏日常入口是Qt Quick原生App，不需要板端浏览器或USB连接电脑查看。先读[App手册](app/板端App使用手册.md)和[图标/离线更新 v4-r2](app/离线更新与图标安装-v4.md)，区分本地离线检测、用户手动WiFi与安装更新。v4-r2正式链接、全屏、常驻、UI退出和180秒检测已验收；systemui重载后的手指图标、独立供电和真实WiFi连接仍待人工验收。

11月15日摄像头已经接通：[接入记录](experiments/2026-11-15/摄像头到位与接入准备记录.md)确认USB相机图像节点为`/dev/video10`（`/dev/video11`是元数据）。[Phase 1终验](experiments/2026-11-15/native-app-usability-v4-phase1-1/report.md)完成连续画面、720×1280全屏和物理拔线TTL；[Phase 2终验](experiments/2026-11-15/native-app-usability-v4-phase2-1/report.md)完成正式图标、单实例常驻、双入口切页、UI退出和196.67秒连续检测。

## 怎样开始读代码

板屏路径先看[本机服务与检测控制](../helmet/app/service.py)、[QML界面](../helmet/app/qml/Main.qml)与[WiFi后端](../helmet/app/wifi.py)，理解令牌、开始/停止、预览原帧/generation/epoch/TTL及用户手动联网。CLI实验再看[命令行入口](../helmet/helmet_realtime.py)与输出接线；两入口复用[输入源](../helmet/sources.py)和[流水线](../helmet/pipeline_runtime.py)。不要一开始就从历史实验脚本读起。

接着看[共享后处理](../helmet/yolo_post.py)：预处理、三个检测头校验、解码和NMS。模型类别中的`person`表示裸头，`hat`表示戴帽头部，不能按全身人物理解。然后阅读[报警状态机](../helmet/alarm.py)、[输出](../helmet/output_sinks.py)和[遥测](../helmet/telemetry.py)，理解什么情况下会提示、保存或隐藏旧结果。

最后看[板端检测导出](../helmet/dump_dets.py)与[评估工具](../helmet/pc/eval_map.py)。学习一条结果怎样从输入图片、模型和阈值关联到原始预测、指标和误检漏检图。`tools_ai/ref/test.py`是上游参考，当前回归在`tests/`和`helmet/tests/`。

## 怎样判断文档中的一句话是否可靠

报告数字应能找到manifest/session，确认输入、模型/源码SHA、尺寸、阈值、计时和退出码。[App终验](experiments/2026-11-15/native-app/validation-manifest.json)绑定新增App短验证；[11月14日验证清单](experiments/2026-11-14/final-validation-manifest.json)绑定原核心实验/CLI包。新旧测试、运行和收据均按自己的身份理解。

静态处理15.5FPS不等于摄像头系统。旧API10供给长跑9.7724/9.7719FPS、新12秒151检测和App短smoke分别归档。最新[App30分钟中文报告](experiments/2026-11-15/原生App30分钟验证报告.md)真实1800.051066秒、19,806检测/19,805输出、11.0030283/11.0024728FPS、360HTTP及直接清理/自动Qt/固定10通过，只限controller/service+QML验证wrapper、20供给/单照片/显式日志与30秒截图，未执行正常launch.py。质量仍是诊断AP50/unknown/最高<85%，S1/S6未闭合。

## 当前离线部署的含义

**已经实现应用级离线运行。** 模型、输入和检测服务在板端，Qt App使用本机回环服务；日常检测无需外网、板端浏览器或电脑页面。正式根为`/userdata/helmet-validation/20261115-native-app-v4-r2-local-2`。SCP更新需要复制时联网；U盘方式保留为候选，本轮未实测。

[当前v4-r2原生包](../dist/helmet-native-app-20261115-v4-r2.zip)为39,227,461B、35 entries，ZIP SHA `14b56543f7aca0b26c61b663770f8bf54729d0ba61a1ac5069f4f1143e084251`；[发布清单](experiments/2026-11-15/native-app/bundle-manifest-v4-r2.json)记录完整载荷。正式根整体解压并逐文件核验，五文件`code_identity`为`7cad142a…`。旧v3包和安装收据保留历史。

两个厂商图标、两个SVG和两个desktop已经指向v4-r2，原cfg和入口备份可查；`apk3.cfg` SHA保持`f64a8e2f…`。`systemui`未自动重启，因此主界面重载后的图标显示和手指点击仍需用户确认。正式链接已直接启动新root、复用同一session并正常退出。

WiFi v3默认扫描等待20秒，真实界面已显示SSID列表与屏幕键盘；用户选择网络、输入密码、主动连接。真实认证、DHCP、保存及失败恢复仍需现场验收。此前v2的8秒超时和旧版失败保留在报告中，不以新列表成功改写旧结果。

目标板需预装兼容Linux/Qt、Python、OpenCV、NumPy、RKNNLite及驱动；ZIP提供应用载荷。真实USB相机、720×1280全屏、物理拔线、resident生命周期和180秒短跑已验证；systemui重载后的手指图标、断USB独立供电、长期现场和真实WiFi认证仍需人工。[历史CLI离线包说明](experiments/2026-11-14/offline-bundle.md)及原v1/v2/v3运行保持自己的SHA与计数。

## 开题和正式提交前的处理

推荐题目为《基于RK3568的离线安全帽检测与状态闭环系统设计与评估》。题目直接对应板端离线运行、原帧新鲜度、故障状态、常驻复用、完整清理和可追溯评价。若学校已登记“轻量化”，先与导师协调题目，再将轻量化解释为现成模型的输入配置和INT8部署取舍，准确说明贡献。

现有Markdown/12页约8分钟正文与HTML演示，可编辑PPTX草稿以[交付导航](deliverables/README.md)最新验证版为准，学校模板/个人信息/日期需填。v4-r2把“离线可用、原生全屏、常驻复用、状态闭环”变成可展示的工程证据；开题仍必须保留85%独立性未知、真实WiFi/长期现场未验等限制。长跑、GUI/RSS、180秒短跑与现场/独立质量分开，不用链接启动或PPT排版补现场通过。

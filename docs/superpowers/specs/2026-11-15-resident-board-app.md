# 板端图标与后台常驻 App 设计

本设计延续用户已授权的毕业计划、多 agent 自主实施、原生离线 App 和手动 WiFi方向。2026-11-15 用户补充：“app可以展示图标，然后点击可以常驻后台，像真正的app一样”。按这一要求交付新的原生版本：点击桌面图标启动；回到桌面/关闭界面继续检测；再次点击唤回当前实例；停止检测与完全退出是明确的两个操作。无需板端浏览器、外网或持续连接电脑。

## 平台、现状与方案选择

实际板端 PID1 为 BusyBox init，未安装 systemctl，Qt5.15.8/qmlscene/Wayland已可用。v3已有两枚厂商图标、普通desktop入口、loopback令牌服务和NPU检测；现launch.py把窗口、服务和检测生命周期绑定，窗口关闭会结束服务。当前无App/NPU任务，governor为rknpu_ondemand。摄像头已由用户报告到位，但新一轮实际USB枚举仍只有root hubs，media图没有绑定sensor；物理采集继续需要新设备/真帧证据。

采用 Python 管理的独立后台进程，沿用POSIX新会话、flock、私有Unix socket与现Qt界面。它适合现BusyBox镜像，避免新增OS服务管理依赖。另一可行路线是systemd用户服务，但本板没有该运行基础；将当前窗口仅改成隐藏而仍依赖启动者进程，不足以证明脱离终端/启动器生命周期后的后台运行。这里选独立后台管理者，由它长期持有唯一实例和资源所有权。

## 用户行为与生命周期

1. 首次点击“安全帽检测”图标打开检测页；首次点击“Wi-Fi设置”图标打开WiFi页。检测仍由用户选择输入/模型并按开始，不因后台启动自动连接网络或自动使用未知相机节点。
2. “回到桌面”按钮和窗口关闭动作隐藏窗口，后台服务和已开始的检测继续。隐藏时暂停画面解码/刷新，保留低频控制状态接收，及时响应再次打开；不把旧图当作恢复后的新图。
3. 再次点击任一图标时复用同一后台管理者、服务、检测generation和源；请求显示对应页，不再启动第二个NPU或重复Qt窗口。Qt调用show/raise/requestActivate只是显示请求，人工屏幕聚焦仍需实物确认。
4. “停止检测”只停本次检测，App后台实例可继续存在；“退出应用”明确退出整个后台App并等待正常资源清理。退出中拒绝新的检测/联网启动；读/SDK/回滚仍阻塞时保留所有者，不假报已经退出、不强杀设备线程。
5. 原检测模型、类别person=裸头/hat=戴帽头部、conf.35/NMS.45/skip0/TTL1、640×480默认相机请求和replay/ responsive配置保持。WiFi仍手动扫描/认证/保存，默认scan20/command2/connect20/rollback5秒保持。
6. 本轮不增加开机自动开始检测；启动来自图标。后台常驻证明进程/检测脱离启动客户端，不等于断电后继续运行、永久无故障或自动恢复NPU。

## 进程与通信边界

- 图标仍调用正常launch.py。日常路径为短命启动客户端→独立resident管理者→正常service.py与Main.qml。启动客户端返回后后台继续；后台管理者负责服务/Qt的启动、退出收据和清理。
- 唯一实例状态位于明确的`/userdata/helmet-validation`私有子目录；跨点击及两个图标共享。采用有生命周期的flock和Linux PID/start token/安装root/版本身份验证；陈旧指针、PID复用、不同安装root活实例、符号链接或不安全权限必须拒绝或在确认原所有者不存在后安全恢复，不能外杀旧实例以取得锁。
- root实施裁定：协调根固定`/userdata/helmet-validation/resident-state`，跨安装root共用；resource lease须由实际service长期持有或继承，不能只靠resident管理者的PID/锁。管理者在child身份发布之前死亡也不能留下允许第二SDK启动的空窗；有活服务/lease时保留原所有者并拒绝新实例。
- Unix socket只承接有限JSON控制命令，例如显示指定页、隐藏、请求退出、只读状态；同UID/peer身份、私有目录/socket权限、请求大小和超时受限。命令不进入shell，不承接密码/模型任意路径/外网接口。
- HTTP仍只监听127.0.0.1且保留现Host/Origin/令牌验证。服务可新增受保护的应用显示/隐藏/退出意图与状态接口，绑定同一应用session；启动、开始/停止、WiFi原接口约束保持。令牌不进入argv/env/日志/导出清单。
- root实施裁定：显示意图使用session UUID和单调sequence/幂等请求标识；resident决定最新desired visibility/tab，QML回报对应序号的实际visible/tab ACK。回包区分请求已受理与Qt已确认；仍不冒称物理聚焦。UI crash后只在再次点击时重建Qt，检测generation保持。
- QML从当前服务状态恢复实际model/source/profile，不把默认下拉框伪装成正在运行的配置。隐藏/再次显示和generation/epoch变化均使旧预览失效；只有新鲜匹配包可呈现。
- 再次显示时刷新可用输入清单，并提供未运行检测时的“刷新输入”操作。复用窗口不再依赖Component.onCompleted重新枚举；刷新不能覆盖正在运行的实际selection。拔出的当前源仍需被明确标识，不能把回放默认1.jpg显示成实际相机源。
- UI意外退出与用户明确完整退出分开处理。意外UI退出不得静默终止正在运行的检测；再次点击可以重开界面。意外服务/后台管理者失败记录实际失败并清理可确认拥有的UI，不自动伪造正常退出或强杀SDK所有者。新启动须先核查旧所有者终态。
- 退出先请求正常停止检测和取消/结束WiFi，等待现有worker/SDK/source所有权释放，再退出HTTP/Qt/后台管理者、释放锁与敏感材料。API的退出已受理不是退出已完成，最终以进程身份/收据/锁和文件终态为准。
- root实施裁定：完整退出进入不可逆stopping，控制socket保留只读退出进度，拒show/start/connect；HTTP停止或UI退出码0都不等于SDK终态。resident TERM/INT走同一正常退出，HUP/点击客户端退场不结束后台；SIGKILL/断电不保证清理。一次性smoke单独分派并遵守同一跨root lease，活resident时拒绝再开SDK。

## 文件、兼容性与发布

新增聚焦的后台管理模块（建议`helmet/app/resident.py`，可按清晰责任再拆小型通信模块），改`helmet/app/launch.py`、`service.py`、`qml/Main.qml`及实际需要的部署清单。模型/共享解码/Pipeline/报警不因本功能改变。

保留现有短验证CLI参数；明确定义短验证为有界一次性路径，不能将它的退出证明冒称日常后台路径通过。后台路径的验证必须从真实正常图标wrapper/launch.py进入，确认客户端退出、同后台PID/start token持续、真实NPU计数在隐藏期间继续、二次启动复用、重现新鲜画面和明确完整退出。

现有v3 ZIP、发布/安装收据、历史根与两份封包手册字节冻结，不覆盖。新版本安装到唯一新root，形成新清单/ZIP与新v4手册。仅在旧App与新试验都终态、载荷核验和审查通过后，使用备份/所有权核验更新本项目拥有的图标入口；不重启厂商桌面，不改无关图标/系统网络。

## 验收与复核

软件测试覆盖：两图标/并发点击只一个管理者和检测；陈旧记录/PID复用/坏权限/坏socket/安装root冲突；隐藏期间检测继续、显示恢复同selection/generation且旧图失效；退出/意外UI退出/服务失败分支；清理未终态拒绝重开；未授权HTTP/control与敏感材料不外泄。Linux进程/锁/socket测试在无NPU隔离fixture运行，宿主平台skip如实记录。

root串行执行板端真实验证：先无NPU图标/后台启动→客户端退场→隐藏/再次打开→正常退出；再固定416/视频回放/responsive由真实界面开始，检查实际配置、鲜JPEG、隐藏期间同NPU会话计数递增、图标复用与退出。先短验证闭合，再延长至至少1800秒并报告时间边界/计数差、独立资源和Qt采样。摄像头新节点可见后另做无NPU真帧、短相机检测/恢复再长跑，不用回放补物理验收。

独立审查分两道：代码符合性/质量，然后原始真实进程、HTTP、Qt、资源与清理证据。应用级离线在只lo UP的子网络命名空间内验证；父网络/WiFi连接不改变。物理图标点击、触摸、独立供电、持续显示、真实WiFi认证/DHCP/保存、独立85%/S1/S6仍只由对应新证据提升。

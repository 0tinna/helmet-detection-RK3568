# App 内网查看与开机后台启动

用户请求：配置同一内网手机通过 IP 查看页面，开机自启动及启动 App 后均可访问。沿用已说明的 `8091` 端口，主代理执行，不使用子代理。

## 实现决定

- 本次为 v4-r2 后的新增版本，旧包、旧根和实验不覆盖。
- App 的令牌控制服务继续只监听 `127.0.0.1`。新增 `0.0.0.0:8091` 只读服务，只提供检测页、状态、对应帧 JPEG/JSON 与 MJPEG；内网不能调用检测、WiFi 或退出控制，也不获得私有令牌。
- 两界面共用 `DetectionController.preview_package()` 已校验的同一 JPEG。不另建 Pipeline、不重编码每次请求、不改变模型/类别/conf .35/NMS .45/skip0/TTL1s 或后处理。
- 手机页带响应式布局、帧号/状态和独立过期计时；请求挂起、解码延迟、停止/源代次变化均不能无限保留旧画面。
- `launch.py --background` 确保同一常驻实例存在而不唤起窗口；开机后台待机，模型/输入与检测仍由板屏手动开始。正常图标打开/切页复用它。
- BusyBox `S99zhelmet-app` 在现有启动脚本之后调用后台入口；不改 WiFi 配置、厂商桌面配置或桌面服务脚本。退出应用后不自动拉起，下一次图标或开机再启动。
- init stop 走正常 quit，并等待同 session 的真实终态、退出收据和锁释放。预算到期返回失败，不以请求受理/HTTP 消失当作已退出。
- 整包在全新 `/userdata/helmet-validation/` 根部署、逐文件校验，再备份/迁移项目自有两个入口、图标/desktop 与新 init 链接。五文件 code_identity 保留，新增文件另由完整包 manifest 校验。

## 接入方式比较

独立 CLI Web 会占用第二路相机/NPU，不能满足同一实例要求；把原本私有 HTTP 控制改为内网监听会改变其控制边界。采用独立只读监听器，共用现有原帧包，保持两类接口职责明确。

## 本轮验证

真实 HTTP 回归验证公共页面/帧与私有控制隔离、TTL/代次/停止、并发客户端与端口释放；Node 执行网页脚本验证独立到期和旧解码回调。常驻测试验证后台创建与图标复用，init 退出不提前成功。板端整体部署后验证正常入口/隐藏/复开、内网 JPEG 与浏览器、180 秒相机运行，以及保存结果后的启动脚本/一次重启恢复。物理手机体验和长期现场如无实测继续列未验。
